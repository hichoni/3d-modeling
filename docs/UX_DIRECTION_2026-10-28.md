# Click Studio 사용성·디자인 개선안 · 2026-10-28

사용자 요청: 1단계 ‘내 맘대로 만들기’의 늦거나 누락되는 버튼 반응을 고치고, Apple의 정돈된 제품 경험과 Nintendo의 조작 피드백을 참고해 전체 품질을 높일 아이디어를 제안한다. 아래는 **제품 개선 제안**이며, 반응성 수정 외 전체 리디자인을 이미 구현했다고 뜻하지 않는다.

## 중심 경험

**“버튼을 고르는 화면”에서 “내 작품을 만지는 작업대”로.** 5분 안에 첫 작품을 만들 수 있도록 선택 이유와 결과를 한눈에 연결한다. 시각 효과는 학생의 조작을 설명하는 데 쓰고 작품의 형태·출력 가능성·현재 상태를 가리지 않는다.

- 첫 10초: 이름 하나를 바꾸거나 추천 작품을 골라 눈앞의 입체가 달라지는 경험.
- 1분: 글씨·그림과 입체 느낌을 결정.
- 3분: 테두리와 키링 칸을 꾸미고 완성 모양 확인.
- 5분: 레이어와 출력 준비로 이동. 디자인 체험 시간과 실제 출력 대기·준비·출력 시간은 따로 표시.

## 1순위: 믿을 수 있는 조작

| 현재 경험 | 제안하는 동작 |
| --- | --- |
| 선택과 계산이 한 덩어리라 느린 계산이 버튼 반응처럼 느껴짐 | 선택 표시를 먼저 그린 뒤 모델 계산. 계산 중에도 다른 선택을 받고 마지막 요청을 적용. |
| 계산 중 다른 키링 칸 클릭이 사라짐 | 현재 작품의 계산을 마친 뒤 마지막으로 누른 칸으로 이동. 대기 상태를 모델 옆에서 설명. |
| 버튼 갱신 때 전체 그림 목록을 교체·스크롤 | 버튼·포커스·목록 위치는 유지하고 선택 상태만 변경. 키보드·터치 모두 같은 위치에서 계속 조작. |
| 잘못된 조합을 고르면 예전 모델이 남아 혼동 | 미리보기에 ‘이 선택은 아직 반영되지 않았어요’와 바로 고칠 행동을 표시. 실제로 보이는 모델과 현재 선택을 혼동시키지 않기. |
| 처음부터 다시 만들기만 있어 탐색이 부담 | 실행 취소/다시 실행, 이전·현재 비교. 디자인·키링 칸 단위로 복구 가능하게 설계. |

반응 시간 목표는 선택 표시 100ms 이내, 일반 미리보기 300ms 이내다. 이는 설계 목표이며 이번 작업에서 저사양 크롬북의 측정값으로 보장한 수치는 아니다. 복잡한 말랑·뚫림의 정확한 메쉬는 시간이 걸릴 수 있다. 장기적으로는 정확한 모델 계산을 Worker로 옮기거나 계산 중 가벼운 미리보기를 먼저 표시하는 방안을 검토한다.

## 2순위: 1페이지를 작품 중심으로

- **작업대:** 현재의 큰 3D 작품과 오른쪽 도구 패널 구조를 살린다. 지금은 도구 패널 전체와 그림 목록 안에 스크롤이 겹쳐 이름 입력이 화면 밖으로 사라진다. 모바일에서도 작품과 현재 편집 칸을 알 수 있게 하고, 독립 스크롤 영역을 줄인다.
- **도구 세 묶음:** 현재 세로로 늘어선 ‘내용 / 입체 / 꾸미기’를 탭으로 구분하고 이름 입력과 현재 선택 요약은 고정한다. 탭을 옮겨도 선택·입력·카메라가 유지된다. 세부 설정은 필요할 때 펼친다.
- **이름·그림:** 6개 안팎의 추천 시작점과 최근 선택, 전체 그림 보기를 제공한다. 글씨체 버튼에는 단순한 이름뿐 아니라 실제 입력한 글자의 작은 견본을 보여준다.
- **입체 느낌:** 볼록·말랑·오목·도장·뚫림을 지금 작품의 썸네일로 비교한다. 선택할 때 깊이 방향을 짧게 보여주고 곧 정확한 고정 시점으로 돌아온다. 사용자가 돌려둔 시점을 매번 초기화하지 않는다.
- **꾸미기:** 테두리·포인트·미리보기 색을 구분한다. 색은 실제 필라멘트 색과 별개임을 가까이 표시한다. 사용할 수 없는 조합은 이유와 대안을 같은 위치에 안내한다.
- **키링 2·3구:** ‘왼쪽/가운데/오른쪽’과 각 칸의 실제 작품 썸네일을 묶어 보여준다. 저장됨·만드는 중·빈칸을 구분하고 전체 세트 미리보기를 제공한다.
- **고정 치수:** 기본 키캡 조각 14×14mm와 별도 큰 도장 20×20mm를 명확히 구분한다. 제작 중인 받침의 규격을 임의 배율로 바꾸는 조절은 넣지 않는다.

## 3순위: 정돈된 화면, 촉감이 있는 피드백

- 배경은 따뜻한 회백색, 텍스트는 짙은 남색. 강조색은 현재 조작·선택·다음 행동에만 사용한다. 모든 카드에 강한 그림자를 넣지 않는다.
- 글자 크기·간격·버튼 높이를 통일한다. 본문은 읽기 쉬운 한글 글꼴, 제목의 둥근 글씨는 포인트로 사용한다. 작은 회색 설명을 줄이고 가장 가까운 조작의 안내로 옮긴다.
- 선택 버튼은 색·테두리·체크를 함께 사용하고 손가락으로 누르기 쉬운 크기를 확보한다. 마우스 올림이 없어도 상태가 명확해야 한다.
- 눌림과 복귀는 짧고 일관되게. 과한 바운스·자동 회전·반복 반짝임은 작품을 확인하는 동작과 충돌하지 않게 제한한다. 모션 감소 설정과 키보드 포커스를 지원한다.
- 클릭이는 요청할 때 도움을 주거나 중요한 한 문장만 말한다. 말풍선의 타이핑으로 작업대 크기가 계속 바뀌지 않도록 공간을 안정화한다.
- 저사양 기기에서는 재질·조명·그림자의 ‘좋아 보임’과 반응성을 함께 측정한다. 정지 중 계속 그리는 렌더링, 긴 메쉬 계산, 썸네일 재생성부터 줄인다.

## 4순위: 슬라이싱·출력도 같은 제품처럼

1. **슬라이싱:** ‘층으로 나누기’를 누르면 현재 모델이 레이어로 이어진다. 재생·층 선택·속 채움 확인의 위계를 분명히 하고 출력 경로가 교육용 연출인지 실제 계산인지 표시한다.
2. **출력 검토:** 작품, 크기, 선택 프린터, 재료, 작품 경로 예상 시간과 프린터 준비 시간을 한 장의 확인 카드로 정리한다.
3. **연결:** 일반 웹+중계기, 크롬북 설치 앱, Android 앱에 맞는 안내만 보여준다. 프린터의 8자리 액세스 코드와 운영자 공유 링크를 같은 종류의 ‘코드’처럼 안내하지 않는다.
4. **출력 중:** 실제 온도·진행 단계와 작품을 함께 보여주고 프린터 연결이 끊기면 추측값으로 계속 진행 중처럼 표시하지 않는다. 딸깍 눌러보기는 출력 명령과 분리한다.
5. **완성:** 내 작품·이름·크기·완성 안내를 작은 작품 카드로 제공한다. 이름이나 작품을 외부 공개하기보다 로컬 저장을 기본으로 한다.

## 작업 순서

1. 이번 반응성 수정·회귀 검사·배포.
2. 1단계 작업대의 한 화면 시안과 실제 터치 조작 검토.
3. 실행 취소·현재 작품 썸네일·키링 칸 상태 표시.
4. 슬라이싱과 출력 검토 카드의 연결.
5. 실제 크롬북·태블릿에서 입력, 빠른 연속 클릭, 복잡한 모델, 글꼴 준비 지연, 화면 회전, 네트워크 단절을 검증.

## 이번에 구현한 범위

`src/app.js`에서 그림 버튼 재생성과 강제 스크롤을 없애고, 선택 표시 후 계산, 입력 디바운스, 한글 조합 보호, 계산 중 마지막 키링 칸 요청 처리, 모델 준비 전·WebGL 없는 칸 전환의 오류 방지를 반영했다. 정확한 기하 계산·슬라이싱 프로필·프린터 명령 형식은 변경하지 않았다. 검증·배포 결과는 [인수인계](HANDOFF.md)의 최신 절을 따른다.
