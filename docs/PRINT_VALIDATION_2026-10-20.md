## 발견한 상태 표시 오류

이전 시작 요청은 밀리초 타임스탬프를 subtask_id로 보냈다. 실물 펌웨어가 이를 2147483647로 제한해, 실제 출력이 진행돼도 웹 작업은 accepted 상태에 머물렀다. 새 작업 ID는 양수 int32 범위로 생성한다. 다른 작업의 ID를 이름만으로 수용하는 보호 규칙은 변경하지 않았다.

최종 M73이 90%인 채 FINISH가 도착하는 문제도 발견했다. 새 파일은 종료 후 M73 P100을 명시하며, 일치하는 작업의 FINISH를 받은 중계기는 완료 진행률을 100으로 정규화한다.

이번 작업은 원래 3MF 해시·프린터 일련번호·고유 작업 이름·출력 중 파일 이름·10층 관측을 확인하고, TLS로 새 FINISH 보고를 받은 뒤 로컬 완료 기록을 복구했다. 원래 기록과 증거를 비공개 runtime에 보존했다. 실제 출력 성공과 웹 추적 오류를 구분한다. 수정된 int32 ID로 추가 실물 출력은 아직 하지 않았다.

## 사진에서 확인된 품질 문제

평평한 윗면 외벽 안쪽에 주기적인 삼각형 빈틈이 있고, 글자 획 중앙에 길쭉한 빈틈이 있다. 바닥면 선도 충분히 합쳐지지 않았다. 가는 실 끌림도 보인다. 단순한 베드 레벨링 문제로 단정하지 않았다.

동일 STL을 설치된 Bambu Studio의 0.20mm Standard / Generic PLA로 계산해 비교했다. 보통 채움 선의 E/mm는 웹 v1 약 0.02743, Bambu 약 0.03073~0.03101이었다. 웹의 공급량이 이 비교에서 약 11% 적었다.

고정된 Kiri 소스의 extrudePerMM은 원형 단면을 층 높이로 비례 축소한다. 웹 설정에서 단순 1.0 배율을 사용해 Bambu의 납작한 비드 단면과 차이가 났다. 이 계산 차이를 보정하며 Generic PLA의 0.98 재료 유량을 적용했다. 해당 Kiri 버전의 solid fill 배율은 내부에서 두 번 적용되므로 설정에는 제곱근을 넣어 중복 보정을 피한다.
