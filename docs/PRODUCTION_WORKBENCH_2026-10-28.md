# 2·3단계 슬라이싱·출력 작업대 · 2026-10-28

부스 체험의 [2·3단계](https://hichoni.github.io/3d-modeling/index.html?start)를 1단계 작업대와 같은 색·카드·버튼 체계로 연결했다. 일반 STL 스튜디오, 슬라이서 프로필, 받침 치수, 프린터 전송 프로토콜은 이번 변경 대상이 아니다.

## 화면 구성

| 영역 | 반영 내용 |
| --- | --- |
| 공통 요약 | 실제 작품 내용 썸네일, 작품 이름, 출력 판 수·치수, 선택/작업 프린터, 시간과 그 의미 |
| 2단계 | 완성 모양 → 층 높이·PLA 선택 → 슬라이싱 → 실제 층별 경로 확인. 계산 전에는 작품을 계속 보여주고 가짜 층수·계산 중 안내를 표시하지 않음 |
| 슬라이싱 카드 | 전체 층·재료량, 접힌 상세 안내, 하단 고정 계산 버튼. 시간은 상단 요약에서 한 번 표시 |
| 3단계 | 내 작품을 크게 보여주는 기본 탭, 별도의 ‘프린터 알아보기’ 탭. 20mm 도장도 내 작품 미리보기 표시 |
| 출력 카드 | 프린터 선택, 실제 상태·진행률·온도, 접힌 재료·자동 보정, 하단 고정 출력/연결 버튼 |
| 연결 전 | 작품과 경로 예상은 확인 가능. 프린터 연결 CTA 및 기기별 안내 표시. 연결되지 않은 기기를 연결됨으로 표시하지 않음 |
| 좁은 화면 | 작품 → 프린터 → 시간 요약, 작품 미리보기, 출력 카드 순서. 집계·중복 매칭 배지와 큰 고정 하단 버튼을 줄이고 페이지 스크롤 사용 |

3구가 모두 채워지면 이름 세 개와 썸네일 세 개를 표시한다. 출력 대상은 기존 규칙의 `printCount()`·`setSlots()`를 따르며, 빈칸을 자동으로 복제하지 않는다. 여러 판의 높이는 서로 다를 수 있어 ‘최대 높이’라고 표시한다. 썸네일은 1단계의 가벼운 면 그림을 재사용하며 정확한 출력 형상의 기준은 큰 3D 모델과 슬라이싱 결과다.

‘디자인 완성’은 화면 속 작품의 편집 상태다. 실제 출력 완료는 프린터 작업이 `complete`일 때만 표시한다. 프린터 학습 모형을 조작해도 출력 명령이나 모의 온도를 실제 상태 카드에 보내지 않는다.

## 시간·연결 상태 규칙

- 브라우저 슬라이싱은 **작품 경로 예상**이다. 예열·자동 보정은 포함하지 않는다. Studio 결과는 **준비 포함 예상**으로 구분한다.
- 출력 중의 **남은 시간**은 최신 프린터 응답에 유효한 `remainingMinutes`가 있을 때만 표시한다. 진행률로 남은 시간을 만들어내지 않는다. 값이 없으면 전체 경로 예상임을 명시한다.
- 목록/작업 API의 마지막 성공 시각을 각각 기록한다. 응답의 `fresh`가 참이면서 마지막 성공 후 15초 이내이고 요청 실패가 없어야 최신으로 취급한다. 5초 간격 화면 갱신으로 응답이 멈춘 상태도 만료시킨다.
- 작업 전에는 선택한 프린터의 목록 상태를 사용하고, 전송 이후에는 **작업에 묶인 프린터와 작업 응답**을 사용한다. 다른 프린터의 최신 상태로 바꾸지 않는다.
- 연결 끊김: 시간 ‘확인 중’, 온도 ‘—’, 오래된 진행률 제거, 중복 출력 비활성. 완료가 이미 확인된 작업은 연결이 끊겨도 완료 결과를 보존한다.
- 일시정지·전송 결과 불명·실패·취소를 구분한다. 진행 중으로 오인할 수 있는 막대 애니메이션은 중단 상태에서 숨긴다.
- 출력 진행·종료 작업의 프린터 선택은 잠근다. ‘같은 작품 다시 준비’나 ‘새 작품 만들기’ 후 새 작업을 준비한다. 기존 안전 확인·서버의 매칭/신선도 검증은 유지한다.

## 소스 위치

- `src/production-status.js`: DOM/전송에 의존하지 않는 상태·시간 문구 계산.
- `src/production-workbench.js`: 공통 요약, 썸네일, 상태 유효기간, 작품/학습 탭, 온도 표시.
- `src/app.js`: 단계 전환·모델 캔버스 이동·슬라이싱 전후 보기·출력 카드 통합.
- `src/connection.js`: 연결/목록/복원 응답에서 유효기간 갱신. UI 콜백을 선택적으로 호출해 연결 모듈 단독 사용 유지.
- `src/printer-tutorial.js`: 학습 모형의 예시 온도를 실제 출력 카드에 표시하던 코드 제거. 설명 모형은 별도 탭을 열 때 처음 생성.
- `src/index.html`, `src/style.css`: 작업대 구조·반응형 배치. `scripts/build.cjs`가 새 모듈을 묶음에 포함.
- `tests/production-status.test.cjs`: 시간 구분, 유효기간·응답 실패, 작업 프린터 고정, 중단·완료 상태, 슬라이싱 전/경로 없는 복원 시 작품 유지.

## 검증

최종 빌드 후 **전체 163개 통과, 실패·취소·건너뜀 0개**. 기존 연결 회귀 검사가 잡은 UI 콜백 의존성을 수정하고 전체 재실행했다. 로그: `artifacts/production-tests-20261028.log`.

Chrome에서 실제 브라우저 슬라이싱으로 `상상` **11층·2분 24초 경로 예상·0.33g**을 확인했다. 1280×640 작업대, 390×844 모바일(스크롤바 제외 CSS 폭 375px), 3구 `상상 · 별 · 달` 이름/세 썸네일, 20mm 도장 미리보기, 프린터 학습 탭을 점검한다. 배포 후 직접 확인한 화면과 최종 Actions 링크는 [HANDOFF.md](HANDOFF.md)에 기록한다.

별도의 로컬 HTTP 모의 서버에서 프린터 01→02 선택, 준비, 출력 37%·남은 3분, 연결 실패, 복구/완료 100%를 검증했다. 이 서버는 프린터 드라이버를 불러오거나 프린터 소켓을 열지 않는다. 모의 시간·온도는 UI 검증 자료일 뿐 실물 측정값이 아니다. **이번 작업에서 실제 프린터로 출력·가열·이동·보정 명령을 보내지 않았다.**

## 배포·인수인계 주의

`index.html`, 공통 빌드 ID가 바뀐 `studio.html`, Windows 운영자 ZIP을 재생성했다. GitHub Pages의 온라인 화면을 새로 열어 반영한다. 이미 실행 중인 로컬 Windows 공방은 최신 ZIP/앱 갱신이 필요하다. IWA/APK는 다시 서명하지 않았으며 기존 설치 묶음의 오프라인 화면은 그대로다. 원본 서명 키 부재·Store 초안 문제의 기존 기록은 계속 유효하다.

실제 ChromeOS/Android의 터치·OS IME·저사양 장시간 성능, 실제 A1 mini로 이 화면에서 출력하는 현장 시험은 별도로 남는다. UI 검증을 새로운 기기 호환성 또는 실물 출력 검증으로 설명하지 않는다.
