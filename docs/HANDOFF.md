## 최신 변경: 실제 웹 슬라이싱

GitHub Pages의 2단계에서 설치 없이 실제 경로를 계산합니다. 웹 엔진 → 중계기 검증·3MF 작성 → 1:1 미니 대기표까지 구현했습니다. 중계기에는 Node.js만 필요하고 Bambu Studio는 선택 대체 계산용입니다. [현재 구조·미검증 범위](WEB_FIRST.md)와 [엔진 재빌드](../tools/slicer/README.md)를 먼저 읽으세요.

실제 브라우저에서 볼록 ‘하늘’, 오목 ‘풍천풍서’를 계산하고, Bambu Studio 경로가 없는 격리 서버에서 ‘수민’의 매칭·접수·운영자 검토를 확인했습니다. 새 웹 엔진으로 실제 프린터를 시작하지 않았습니다. 다음 현장 작업은 한 대에서 첫 층·종료·글자·압입 확인, 그 뒤 실제 ChromeOS와 6대 동시 시험입니다. 기존 실물 FINISH 기록은 Bambu CLI 출력입니다.

최신 변경은 `src/browser-slice-worker.js`, `src/browser-slicer.js`, `src/toolpaths.js`, `bridge/browser-job.cjs`, `bridge/profiles/`, `tools/slicer/`에 있습니다. 기본 앱 수정은 `node scripts/build.cjs`, 엔진 설정 변경은 그 전에 `node tools/slicer/build.cjs`가 필요합니다. 개인정보·프린터 접근 코드는 계속 `runtime/`에만 둡니다.

## 크롬북·여러 미니를 현장에서 1:1 매칭

**[현장 매칭 안내](FLEET.md)**를 먼저 보세요. 공방 PC 한 대에 미니 여러 대를 등록하고 공통 부스 링크를 공유합니다. 각 크롬북에서 현장의 비어 있는 미니를 선택해 매칭·해제·재매칭합니다. 각 크롬북의 운영자 PIN은 현재 매칭된 미니만 제어하고, 중앙 PC는 전체를 관리합니다. 설정 ZIP과 CMD는 웹의 ‘운영자 처음 설정’에서 내려받습니다.

## 새 컴퓨터에서 시작하기

저장소를 내려받고 Node.js 20 이상을 설치합니다. Windows 기본 Bambu Studio 경로를 지원합니다. `start-workshop.cmd`를 더블클릭하거나 아래 명령을 실행하세요.

```powershell
node bridge/setup.cjs
node bridge/server.cjs
```

- 프린터 없이 작업할 때는 설정 질문의 IP를 비워둡니다. 모델링과 실제 슬라이싱은 가능합니다.
- 브라우저 주소는 **http://127.0.0.1:5188/** 입니다. `localhost` 대신 이 주소를 사용하세요.
- 운영자 PIN은 시작 터미널과 비공개 `runtime/config.json`에 있습니다. PIN으로 운영자 화면을 열 수 있습니다.
- Bambu Studio 설치 위치가 다르면 `runtime/config.json`의 `slicerPath`를 바꿉니다. 필요한 경우 `profilePath`로 `resources/profiles/BBL` 경로도 지정합니다.
- 서버를 종료하려면 실행한 터미널에서 Ctrl+C를 누릅니다. 서버 종료가 이미 시작된 프린터 출력을 중지하지는 않습니다.

## 학교 프린터 연결 복원

1. 현장 PC와 A1 mini를 같은 Wi-Fi 네트워크에 연결합니다. **Wi-Fi도 LAN 연결입니다.** 유선 케이블을 의미하지 않습니다.
2. 프린터 본체에서 LAN Only와 Developer Mode를 켭니다. 클라우드/Handy 연결 방식과 달라집니다.
3. `node bridge/setup.cjs`로 현재 IP와 일련번호를 입력합니다. 학교에서 쓰던 IP를 집에서 그대로 사용하지 마세요.
4. 접근 코드는 그 PC의 Bambu Studio에 저장된 값을 읽습니다. 없으면 비공개 `runtime/config.json`의 `printers` 항목의 `accessCode`에 입력합니다.
5. 운영자 화면에서 연결 상태를 확인합니다. 서버는 로컬 검색으로 **A1 mini / LAN 모드**를 확인하고, MQTT·FTPS TLS 인증서를 검증합니다.
6. 연결 실패 시 같은 네트워크, 본체 모드, IP 변경, 접근 코드, 방화벽의 로컬 검색 허용 여부를 확인합니다. Windows 보안 설정을 앱이 자동으로 바꾸지는 않습니다.

학교 장비의 실제 IP·일련번호·접근 코드와 시험 출력 파일은 **GitHub에 포함하지 않았습니다.** 새 PC에서는 새로 설정해야 합니다. 원래 PC의 비공개 설정과 로그는 `runtime/`, `artifacts/`에만 남아 있습니다.

## 확인 완료와 후속 확인

완료: 이름/그림 모델링, 고정 외곽, 볼록/오목, 층 체험, 실제 슬라이싱, 실제 경로, 대기표, 운영자 잠금, 수동 확인 후 전송, 중복 시작 차단, MD 정리.

학교에서 실제 확인: 기존 사용자 STL을 웹에서 보내 A1 mini 출력 완료까지 확인. 새 UI 모델은 실제 슬라이싱까지 확인했고 추가 물리 출력은 시작하지 않았습니다.

현장 후속 확인:

- 완성된 14mm 조각이 제작 중인 받침에 적절히 압입되는지 확인. 받침 외곽을 바꾸는 옵션은 제공하지 않습니다.
- 작은 이름 4자·작은 장식·음각이 0.4mm 노즐에서 충분히 또렷한지 샘플로 판단.
- 필요한 경우 전체 새김 높이의 기본값만 0.8→1.0mm로 변경. 바닥과 외곽은 유지.
- 한 번에 여러 작품을 배치해 출력하는 기능은 아직 없습니다. 각 미니에서 작품 하나씩 운영자가 시작하며 다른 미니는 동시에 출력할 수 있습니다.
- 여러 크롬북과 여러 미니의 현장 1:1 매칭·해제·재매칭과 프린터별 접수를 구현했습니다. 부스 모드를 설정한 PC만 LAN 접수를 열며, 실제 ChromeOS와 학교 네트워크의 통신 허용 여부는 현장에서 확인해야 합니다.
- 물리 결합 및 새 UI에서 생성한 각 디자인의 실물 품질은 자동 테스트가 보장하지 않습니다.

참가자 이름과 STL은 로컬 작업 폴더에 남습니다. 행사 종료 후 필요한 파일만 비공개로 보관하고, `runtime/jobs`는 서버를 종료한 상태에서 백업·정리하세요. 200개 보관 한도를 두었습니다. GitHub에 올릴 때 `.gitignore`를 유지하고 `git add -f runtime`을 사용하지 마세요.

## Windows 실행 차단 · 2026-10-20

확인한 PC에서 Smart App Control이 켜져 있으며 cmd.exe에 서명 수준 제한이 적용된 로그를 확인했습니다. 현재 운영자 ZIP은 서명 전 개발용입니다. 사이트와 ZIP에 [차단 안내](SMART_APP_CONTROL.md)를 추가했고, 학교 정책을 우회하는 실행 방법은 제공하지 않습니다. 정식 서명 배포에 필요한 배포자 인증과 서명 자격 증명이 없어 이 PC의 실행 차단 해결은 완료되지 않았습니다. 공개 웹 모델링·STL 저장과 승인된 Bambu Studio의 수동 출력은 별도로 가능합니다.

## Windows 설치 앱 · 개인 명의 Store · 2026-10-20

사용자는 Store 설치가 가능하다고 확인했고, 학교·기관 명의 대신 개인 명의 배포를 최종 선택했습니다. `desktop/`에 .NET 10 네이티브 설정 앱과 Node 포함 MSIX 빌드를 추가했습니다. [사용자 준비물과 빌드](WINDOWS_APP.md), [Store 제출 초안](STORE_SUBMISSION.md), [개인정보 안내 초안](PRIVACY.md)을 참고하세요.

실제 Partner Center 계정 본인 확인·앱 이름 예약과 공개 식별값 세 개가 필요합니다. 이름을 추측하거나 임시 Publisher를 정식 신원처럼 사용하지 않습니다. 계정 인증이 끝나기 전에는 정식 서명 앱이나 Store 설치 링크를 제공할 수 없습니다. 초기 시험 MSIX는 설치용 공개 링크로 연결하지 않습니다.

## 최우선 제품 방향 정정 · 2026-10-20

사용자는 Windows 운영 앱 출시가 아니라 크롬북·노트북에서 웹 모델링·실제 슬라이싱·Bambu 로컬 출력을 끝내는 제품을 원한다고 재확인했습니다. 공용 노트북 한 대 추가는 가능하지만 사용자 경험은 웹이어야 합니다. [웹 중심 목표](WEB_FIRST.md)를 다음 작업의 기준으로 삼으세요. Store 계정·신원 확인을 먼저 요구하는 단계로 진행하지 않습니다. 기존 Windows 앱은 전송 중계기용 보조 자산으로 유지합니다.

Windows 앱의 후속 격리 빌드는 성공했습니다. 포트 사용 확인을 짧은 TCP 연결 시간 초과로 판단하던 오류를 고쳤고 설정 저장·중복 장비 거부·공개 구성 해시·프린터 없는 서버 시작/안전 종료 자체 시험을 통과했습니다. 실제 프린터 명령은 0회입니다. Store 서명·설치는 검증 전입니다.
