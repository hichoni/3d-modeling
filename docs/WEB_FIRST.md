# 웹에서 만들고, 슬라이싱하고, 매칭한 미니로 보내기

2026-10-20 구현·검증 기준입니다. 참가자는 크롬북이나 노트북의 브라우저 하나를 사용합니다. 중심 제품은 **상상을 클릭하다! — 3D 키캡 클리커 만들기** 웹 체험이며, Windows 앱은 중계기 배포의 선택 수단입니다.

## 지금 구현된 흐름

크롬북·노트북 웹 → 모델링 → 실제 웹 슬라이싱 → 층별 노즐 경로 → 출력 대기표 → 공용 노트북 중계기 → 현장에서 1:1 매칭한 A1 mini.

- GitHub Pages만 열어도 모델링과 **실제 브라우저 슬라이싱**이 됩니다. 슬라이서 설치, 서버 계산 요청, 외부 CDN이 필요하지 않습니다.
- 2단계의 ‘이 브라우저에서 슬라이싱!’을 누르면 Web Worker가 외벽·채움·압출 경로를 생성합니다. 주황색 선은 그 결과입니다. 계산 전 화면은 원리 체험으로 표시합니다.
- 시간·PLA 무게는 **작품 경로만**의 추정입니다. 예열·보정·재료 로딩·퍼지·종료 동작과 그 재료 사용량은 별도입니다. 5분은 디자인 체험 시간입니다.
- 현장 중계기에 연결하고 미니를 매칭하면 경로와 STL을 접수하고 대기표를 받습니다. 중계기는 다시 슬라이싱하지 않고 검증한 경로를 프린터용 파일로 묶습니다. 이 경로에는 Bambu Studio 설치가 필요하지 않습니다.
- 운영자가 PIN, 빈 베드, 0.4mm 노즐·외부 PLA·텍스처 PEI 및 시험 프로필 확인을 거쳐 웹에서 시작합니다. 다음 작품은 자동 출력하지 않습니다.
- 설치된 Bambu Studio CLI 계산은 운영자용 대체 기능으로 남아 있으며 선택했을 때만 사용합니다. 웹 엔진 결과와 구분해서 표시합니다.

일반 브라우저는 A1 mini의 원시 TCP FTPS·MQTT 연결을 직접 열 수 없습니다. 따라서 공용 노트북 등의 **로컬 중계기는 여전히 필요**합니다. 크롬북 6대 + 미니 6대만의 무설치 직결을 완성했다고 주장하지 않습니다. 학교 Wi-Fi가 기기 간 통신을 차단하면 현장 네트워크 설정도 필요합니다.

## 엔진과 고정 규격

Kiri:Moto 4.7.0 FDM worker를 [고정 커밋](https://github.com/GridSpace/grid-apps/tree/d138275bbe9d4e4030d8cb8b2dcf66607da9295a)에서 번들했습니다. 재빌드·잠금 파일·해시는 [tools/slicer](../tools/slicer/README.md)에 있습니다. 기존 r128 화면 렌더러와 엔진의 Three 의존성은 별도 영역입니다.

- 외곽 14 × 14mm, 모서리 R2.8, 바닥 1.5mm, 모델 전체 높이 2.1~2.5mm
- A1 mini 180mm 베드의 중앙 X/Y=90mm, 0.4mm 노즐, PLA 1.75mm
- 0.2mm 층, 선폭 0.42mm, 외벽 2줄, 위·아래 3층, grid 채움 15%
- 노즐 220°C / 텍스처 PEI 65°C / 외부 스풀 / AMS 미사용
- 0.2mm 층 양자화로 최종 압출 Z는 모델 높이와 약 0.1mm 차이가 날 수 있습니다. 2.5mm 모델은 엔진 결과에 따라 13층·Z2.6mm가 될 수 있습니다. 끼움과 얇은 획은 첫 실물 시험에서 확인해야 합니다.

## 파일과 프린터 명령의 경계

브라우저의 .paths.gcode 저장은 **경로 검토용**입니다. 가열·홈·준비·종료 동작이 없으므로 프린터에 그대로 넣는 파일이 아닙니다.

POST /api/browser-jobs는 부스 키·기기 토큰·매칭·CSRF를 확인하고 고정 규격 STL과 경로를 검사합니다. 임의 기계 명령, G91, 다른 팬, 외곽·높이 이탈, 과도한 속도·압출·리트랙션·대기, 층 누락을 거절합니다. 원문 주석을 붙이지 않고 검증된 명령만 다시 작성합니다.

중계기는 [고정 A1 mini 준비·종료 절차](../bridge/profiles/a1-mini-pla.json)를 추가합니다. 이전 실물 출력이 완료된 Bambu Studio 02.07.01.62 / 20260513 A1 mini 프로필의 생성 결과에서 분리했습니다. A1 256mm 프로필을 사용하지 않습니다. 원본 시작·종료 프리셋과 AGPL 라이선스도 같은 폴더에 있습니다. **새 웹 엔진과의 조합은 아직 실물 출력하지 않았습니다.**

3MF에는 STL 모델, N1 대상 식별, 0.4mm 노즐·PLA 정보, G-code MD5가 들어갑니다. 서버 파일 SHA-256, 프린터 일련번호, 매칭 revision을 시작 직전에 재확인합니다. 모델의 M82 절대 압출과 기계 종료의 M83 상대 압출을 명시적으로 전환합니다.

3MF prediction의 준비 시간 365초는 과거 Bambu 결과의 총 514초−모델 149초에서 얻은 참고값이며 실측 보장이 아닙니다. 웹에는 이를 정밀한 전체 시간으로 표시하지 않습니다.

## 확인한 것과 남은 것

확인: 실제 Chromium에서 ‘하늘’ 볼록 11층·약 2분 15초·0.27g, ‘풍천풍서’ 오목 11층·약 2분 23초·0.30g 계산. Bambu Studio 경로가 없는 격리 중계기의 CSP 환경에서 ‘수민’ 11층 경로 생성 → 매칭 → 대기표 #001 → 운영자 검토까지 확인했습니다. 이번 시험에서는 프린터 명령을 보내지 않았습니다.

자동 검사: 실제 번들 엔진의 볼록·오목·높이별 계산, 외부 네트워크 없는 worker, 경로 차단 규칙, 3MF·MD5·SHA, Bambu Studio 없는 HTTP 접수, 인증과 기존 1:1 분리를 검사합니다. [검증 기록](VALIDATION.md)에 자세히 적었습니다.

남은 현장 검증:

1. 준비한 A1 mini 한 세트에서 **새 웹 엔진 + 기계 wrapper + 3MF** 조합의 수신·첫 층·종료·글자·받침 결합 확인. 기존 Bambu CLI 출력 성공과 구분합니다.
2. 실제 학교 ChromeOS에서 성능·메모리·관리 정책·로컬 네트워크 허용 확인.
3. 크롬북 6대 + 미니 6대의 동시 접수·분리·해제·재매칭·장애 복구 확인. 두 대 모의 시험을 6대 실물 검증으로 간주하지 않습니다.
4. 학교 정책에 막히는 PC의 중계기는 승인된 배포 경로 준비. 개인 Store 등록·신분 확인·제출은 아직 하지 않았으며 웹 엔진 검증보다 먼저 해야 하는 필수 단계가 아닙니다.
