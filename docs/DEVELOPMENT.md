# 개발 구조와 다음 개선

## 의도

초안의 많은 옵션을 한 화면에 나열하는 방식에서, 참가자가 선택→문자→입체→완성을 순서대로 경험하는 방식으로 바꿨습니다. 출력 설명은 완성 화면과 운영 안내에 배치했습니다. 타이머는 압박이나 강제 초기화에 사용하지 않습니다.

## 실행/빌드

- 외부 프레임워크와 npm 설치 없이 동작하는 HTML/CSS/JavaScript입니다.
- `scripts/build.cjs`는 HTML 템플릿, CSS, JavaScript, 4개 TTF, 제3자 라이선스를 단일 `index.html`에 넣습니다.
- `src/`만 수정한 뒤 반드시 `node scripts/build.cjs`를 실행합니다.
- 외부 요청, 로그인, 데이터베이스, 분석 SDK, 서비스 워커는 없습니다.
- 미리보기 서버는 `127.0.0.1:5186`에만 바인딩합니다. 현장에서는 서버 없이 HTML을 직접 열 수 있습니다.

## 데이터 흐름

1. `state.js`의 `S`가 현재 디자인 상태를 가집니다. 메모리에만 존재합니다.
2. 입력 변경마다 `revision`을 올리고 이전 모델의 저장을 비활성화합니다.
3. 해당 글꼴을 로드한 뒤 Canvas 2D로 도장 인영을 만듭니다.
4. marching squares로 윤곽을 추출하고 단순화합니다. 포함 관계로 외곽/구멍을 나눕니다.
5. Three.js로 밑판/새김/손잡이를 만듭니다. 확대된 글씨는 밑판 외곽에 맞춰 잘라냅니다.
6. 3D와 실제 찍힌 모양을 갱신합니다. `builtRevision === revision`일 때만 저장을 허용합니다.
7. 완성 시 제작 번호와 디자인 시간이 고정됩니다. 이전 단계에서 편집하면 새로운 완성 기록을 만듭니다.
8. STL은 binary little-endian, ZIP은 비압축 UTF-8 파일명과 CRC-32를 사용합니다.

## 기본 제한

| 항목 | 현재 범위 |
| --- | --- |
| 문자 | 한글 완성형/자모, 영문, 숫자 / 최대 6자 / 공백 제거 |
| 가로/지름 | 18–36 mm |
| 세로(타원/직사각) | 18–42 mm |
| 바닥 | 2–5 mm |
| 새김 | 0.8–2 mm |
| 손잡이 | 8–20 mm |
| 테두리 | 0–2 mm |
| 획 보강 | 0–0.4 mm |
| 반전 | 도장 용도에 맞춰 항상 켜짐 |

한글 입력 중간에 문자열을 자르지 않도록 IME 조합 완료를 기다립니다. 이모지·한자·특수문자는 기본 지원 대상에서 제외하며 저장을 막습니다. 파일명은 파일 시스템 예약 기호를 제거합니다.

## 기하학적 한계

- 기존 초안의 겹치는 닫힌 메쉬 방식입니다. 전체 모델을 단일 Boolean union으로 만드는 기능은 없습니다.
- 밑판/글씨는 약 0.02 mm 겹치고, 손잡이와 방향 표시 돌기도 겹치게 구성합니다. 슬라이서별 병합 동작은 확인해야 합니다.
- 래스터 윤곽을 간략화하므로 극도로 얇은 획과 작은 글씨는 일부 손실될 수 있습니다.
- 판형보다 손잡이 모델의 오버행이 큽니다. ‘무서포트 보장’ 문구는 사용하지 않습니다.
- STL에 색상은 없고, 화면의 색은 시각화용입니다.
- 실제 프린터와 슬라이서 시험 없이 ‘출력 가능 인증’이나 출력 시간 추정치를 제공하지 않습니다.

## 확장 우선순위

1. **사용할 프린터로 기준 샘플 출력:** 적정 글자 크기, 획 두께, 소재, 속도 확정.
2. **장비 프로필:** 행사별 치수/손잡이 제한을 참가자 UI에 적용.
3. **단일 솔리드 출력:** 검증된 Boolean 엔진으로 메쉬 합집합을 만든 뒤 STL/3MF 내보내기. 파일 크기와 오프라인 실행성을 함께 검토.
4. **운영자 접수함:** 실제 서버/저장소/개인정보 정책이 정해진 뒤 구현. 현재 다운로드는 접수함이 아닙니다.
5. **설정 다시 불러오기:** 버전/입력값 검증 후 JSON 재편집. 현재 JSON은 기록용입니다.
6. **접수 배치 출력:** 제작 번호를 물리적으로 구분하는 트레이 또는 배치 도구.

이 항목들은 현재 구현되지 않았으며 후속 개발 제안입니다.
