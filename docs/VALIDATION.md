- Chromium UI: ‘하늘’ 볼록 11층·2분 15초·약 0.27g, ‘풍천풍서’ 오목 11층·2분 23초·약 0.30g. 실제 슬라이더 경로 전환과 모델 수정 후 이전 계산 초기화를 확인했습니다. 수치는 작품 경로 기준입니다.
- Bambu Studio 실행 경로가 없는 격리 중계기에서 CSP의 WASM/Blob Worker 실행 → ‘수민’ 11층·2분 09초·약 0.28g → 1:1 시험 미니 매칭 → 웹 대기표 #001 → PIN 운영자 검토 확인.
- 자동 검사 29개: 실제 엔진의 높이별 볼록·오목 계산, 외부 fetch/import 금지, 소스·번들 해시, 경로 명령·좌표·압출 차단, 3MF/MD5/SHA, Studio 없는 API 접수·시작 거절, 기존 인증·매칭·두 프린터 분리, 공개 ZIP 의존성 검사.
- 새 API의 격리 시험에는 프린터 IP가 없습니다. 실제 FTPS 업로드·출력 시작은 **0회**입니다. 새 조합의 3MF 펌웨어 수용·첫 층·출력 완료·받침 압입과 ChromeOS/6대 실물 시험은 미검증입니다.
- 로컬 검증 산출물: Git 제외 `artifacts/browser-proof/`의 화면과 시험 3MF. 공개 저장소에 실제 이름·접근 코드·IP를 포함한 운영 기록은 올리지 않습니다.

이하의 이전 Bambu CLI 실물 기록은 새 웹 엔진 실물 검증을 의미하지 않습니다.

## 운영자 설정 파일 다운로드 — 2026-10-20

부스 연결 창의 ‘운영자 처음 설정’에 ZIP과 configure-booth.cmd 다운로드를 추가했습니다. ZIP은 공개 파일 허용 목록으로 구성한 약 4.7MB 묶음이며 설정 CMD, 실행에 필요한 Node 모듈, HTML, PowerShell 실행 도구, 안내와 라이선스를 포함합니다. 개인 runtime, 프린터 접근 코드, 출력 작업은 제외합니다. 자동 검사 21개 통과 및 Windows Expand-Archive 압축 해제 확인. 패키지의 상대 모듈 의존성 누락과 기본 설정의 비공개 값 포함 여부도 검사합니다.

## 여러 미니 · 현장 1:1 매칭 — 2026-10-20

이전 공유 프린터 방식에서 **각 크롬북이 현장에서 빈 미니를 선택하는 1:1 매칭**으로 확장했습니다. 여러 미니를 등록하고, 안전한 해제·재매칭, 분실 기기의 중앙 해제, 각 크롬북의 해당 미니 전용 운영자 PIN, 프린터별 독립 출력 상태를 구현했습니다. 기존의 ‘운영자 제어는 출력 PC에서만’이라는 설명은 이 버전에서는 중앙 전체 관리 권한에만 해당합니다.

자동 검사 24개 통과. 새 검사에서는 프린터 ID/IP/일련번호 중복 거부, 매칭 유일성과 재시작 복원, 출력 중 교체 금지, 재매칭 시 이전 접수 취소·버전 무효화, 기기별 PIN 토큰 범위, 다른 크롬북 작업 접근 거부를 확인했습니다. 모의 프린터 두 대에 독립적으로 시작·진행·중지·완료 상태를 주입해 미니 1의 작업과 명령이 미니 2로 섞이지 않는지 확인했습니다.

**여러 실제 미니의 동시 물리 출력과 실제 ChromeOS의 현장 매칭 UI는 아직 실기 검증하지 않았습니다.** 기존 단일 A1 mini 출력 완료 증거와 이번 다중 프린터 모의 검사를 구분합니다. 브라우저 자동화가 앱 설정에서 비활성화되어 새 화면은 코드·DOM 요소 연결과 API로 검증했습니다. 새 설정 ZIP에는 다중 프린터 모듈과 현장 매칭 안내를 포함합니다.

격리된 다중 프린터 설정의 LAN API에 두 기기를 각각 mini-01/mini-02로 매칭한 뒤 실제 Bambu Studio CLI로 각 작품을 슬라이싱했습니다. 11층 결과가 원래 선택한 대상과 함께 접수되어 대기표 1/2를 발급한 것을 확인했고, 시험 미출력 접수와 매칭은 해제했습니다. 이 검증 서버에는 실제 프린터 주소를 넣지 않았으며 프린터 명령은 0회입니다.


## Windows 보안 차단 확인 · 2026-10-20

Smart App Control On 상태, Code Integrity 3033의 cmd.exe 실행 제한 기록, cmd.exe와 설치 Node.js의 유효한 Authenticode 서명을 읽기 전용으로 확인했습니다. 특정 알림의 최종 차단 주체는 확정하지 못했으며, 보안 설정 변경이나 다운로드된 차단 파일의 재실행은 하지 않았습니다. 정식 서명 전 개발용임을 사이트·ZIP·문서에 표시했습니다. SAC 환경 설치 성공은 검증되지 않았고 해결 완료로 주장하지 않습니다.

## Windows 네이티브 앱과 MSIX · 2026-10-20

CMD/PowerShell 실행 체인을 사용하지 않는 네이티브 설정 앱을 컴파일하고 Microsoft MakeAppx의 구조 검사를 통과했습니다. 포함된 Node 공식 배포본의 SHA256과 OpenJS 서명, Microsoft 빌드 도구의 서명을 확인했습니다. 웹·서버 자동 검사 25개와 PowerShell 빌드 스크립트 구문 검사를 통과했습니다. 새 앱의 서명 전 EXE를 현재 PC에서 시험하던 중 앱 제어 정책이 실행을 차단해 로컬 실행 시험을 중단했습니다. 격리 Windows 빌드 작업에서 앱의 자체 시험을 진행하며, 실제 프린터 출력 명령은 보내지 않습니다. 정식 서명·Store 심사·학교 설치 검증은 아직 완료되지 않았습니다.

후속 Windows 격리 검사 성공: 커밋 d0d8ff2, GitHub Actions 39363912741. 자체 시험 결과 configuration/duplicateDeviceGuard/payloadHashes/isolatedServerStartStop 모두 pass, printerCommands=0. 이 검사는 Store 서명 설치 또는 학교 PC 정책 통과의 증거가 아닙니다. 사용자의 최종 웹 중심 요구는 WEB_FIRST.md에 별도로 기록했습니다.
