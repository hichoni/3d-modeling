# 여러 A1 mini · 크롬북 현장 1:1 매칭

한 크롬북은 그때 선택한 미니 한 대에 연결됩니다. 현장에서 비어 있는 미니를 선택하고 필요하면 해제·재매칭합니다. 한 미니를 두 크롬북이 동시에 차지할 수 없습니다.

```text
크롬북 01 ↔ 미니 02
크롬북 02 ↔ 미니 01
크롬북 03 ↔ 미니 03
          ↓
공방 PC 한 대: 슬라이싱 + 각 프린터의 개별 연결 관리
```

크롬북마다 PC나 Bambu Studio를 설치하는 구조가 아닙니다. 공방 PC 한 대가 여러 미니에 각각 연결합니다. 웹 슬라이싱 계산은 각 브라우저가 처리하고, 서로 다른 미니의 실제 출력은 독립적으로 진행할 수 있습니다.

## 출력 PC 최초 준비

현재 설정 ZIP은 서명 전 개발용입니다. Windows가 실행을 차단한다면 [보안 차단 안내](SMART_APP_CONTROL.md)를 확인하고 학교의 승인된 배포 절차를 사용해야 합니다.

1. [운영자 설정 ZIP](https://hichoni.github.io/3d-modeling/downloads/booth-setup.zip)을 내려받아 폴더에 압축 해제합니다.
2. Windows 출력 PC에 Node.js 20 이상을 준비합니다.
3. `configure-booth.cmd`를 실행하고 **등록할 미니 대수**를 입력합니다. 최대 32대를 등록할 수 있습니다.
4. 각 미니의 표시 이름·IP·일련번호를 차례로 입력합니다. 실제 본체에도 같은 번호를 붙여주세요.
5. 각 미니에서 LAN Only와 Developer Mode를 켭니다. 접근 코드는 PC의 Bambu Studio에서 읽거나 비공개 `runtime/config.json`의 `printers`별 `accessCode`에 입력합니다.
6. 참가자와 같은 Wi-Fi의 **PC 주소**를 선택합니다. 프린터 주소와 다릅니다.
7. PC의 운영자 화면을 PIN으로 열고 부스 링크를 공유합니다. 모든 크롬북이 같은 부스 링크를 사용하고, 프린터 선택은 현장에서 합니다.

이미 구버전 서버가 실행 중이면 종료한 후 새 서버를 시작해야 합니다. PC 한 대에서 같은 포트의 서버를 두 개 실행할 필요가 없습니다. 개별 프린터 연결만 다시 시도할 때는 운영자 화면의 해당 미니를 선택하고 ‘프린터 다시 연결’을 사용합니다.

## 각 크롬북에서 매칭

1. 같은 Wi-Fi에서 부스 링크를 엽니다. Chrome이 로컬 네트워크 연결을 물으면 허용합니다.
2. 화면 위 **미니 매칭**을 누릅니다.
3. 기기 이름을 ‘크롬북 01’처럼 알아보기 쉽게 입력합니다.
4. 본체 번호와 일치하는 미니를 선택합니다. 다른 기기가 사용하는 미니는 선택할 수 없습니다.
5. 화면에 **크롬북 01 ↔ 미니 02**처럼 현재 매칭이 표시됩니다.
6. 이름/그림 모델링 → 실제 슬라이싱 → 출력 접수를 진행합니다. 작품에는 접수 당시 미니와 매칭 버전이 기록됩니다.
7. 이 크롬북의 ⚙ 화면에서 운영자 PIN을 입력합니다. 매칭된 미니의 빈 베드·PLA를 확인한 뒤 출력을 시작합니다. 중앙 PC에서도 같은 작업을 관리할 수 있습니다.

한 번 매칭한 브라우저는 같은 부스 링크 또는 기본 Pages 주소에서 매칭을 복원합니다. 새 참가자 시작은 디자인만 초기화하고 크롬북↔미니 매칭은 유지합니다. 매번 링크를 새로 만들 필요가 없습니다.

## 다른 미니로 변경하기

‘미니 매칭’을 열어 현재 매칭을 해제하거나 비어 있는 다른 미니를 선택합니다. 미출력 접수가 남아 있으면 **기존 미출력 접수 취소**에 체크해야 합니다. 기존 작품을 새 프린터로 몰래 바꿔 보내지 않습니다. 변경 후 새 미니에서 다시 계산·접수하세요.

- 슬라이싱 중이면 계산이 끝난 뒤 변경합니다.
- 출력 준비·출력·일시 정지·시작 결과 불확실 상태에서는 매칭을 바꿀 수 없습니다.
- 매칭 변경 후 기존 운영자 토큰은 무효가 됩니다. 새 미니에서 운영자 PIN으로 다시 잠금을 해제합니다.
- 다른 기기가 사용하는 미니를 임의로 빼앗을 수 없습니다.

## 중앙 PC에서 유연하게 관리하기

중앙 PC의 ⚙ 화면에서 **미니 이름 ↔ 기기 이름** 전체 목록을 봅니다. 크롬북이 고장 났거나 브라우저 저장 정보가 지워졌다면, 해당 미니가 출력 중이 아닌지 확인한 뒤 중앙에서 매칭을 해제하고 새 크롬북으로 다시 매칭합니다. 중앙 해제는 해당 기기의 미출력 접수를 취소합니다.

운영자 화면의 프린터 선택 상자에서 미니별 연결 상태·중지 대상을 선택합니다. 접수 작품을 선택하면 해당 미니가 자동 선택됩니다. 한 미니의 출력 시작/중지가 다른 미니에 전달되지 않도록 서버에서 대상과 권한을 확인합니다.

기본 운영자 PIN은 공방 공통입니다. 필요하면 비공개 설정의 각 `printers` 항목에 `operatorPin`(6~12자리)을 추가해 미니별 PIN을 사용할 수 있습니다. 프린터의 네트워크 접근 코드와 운영자 PIN은 서로 다른 값입니다.

## 프린터 추가·주소 변경

`configure-booth.cmd`를 다시 실행해 등록 대수와 각 미니의 정보를 수정합니다. 기존 슬롯의 ID를 유지하고 이름만 바꾸면 현장 기기에서 알아보기 쉽습니다. 프린터의 실제 일련번호가 바뀌면 이전 접수 작품을 새 하드웨어에 그대로 전송하지 않고 재접수를 요구합니다. 설정 변경은 출력 상태를 확인한 뒤 서버를 재시작해 적용합니다.

매칭은 비공개 `runtime/pairings.json`에 저장합니다. 직접 수정하기보다 중앙 운영자 화면에서 해제하세요. 해당 파일과 운영자 PIN·프린터 접근 코드는 공개 저장소나 참가자 링크에 포함하지 않습니다.

## 검증 범위

자동 검사에서 미니 2대의 독립 출력 명령·진행 상태·중지, 크롬북 2대의 서로 다른 매칭, 타 기기 작업 접근 차단, 재매칭 후 이전 접수 무효화, 출력 중 매칭 변경 차단을 확인했습니다. 출력 명령 검사는 **모의 프린터**로 수행했으며 실제 여러 미니의 동시 실물 출력 시험은 아직 하지 않았습니다. 학교 크롬북과 Wi-Fi의 로컬 접근 권한·기기 격리 여부도 현장에서 확인해야 합니다.
