# 크롬북에서 링크만 열어 체험하기

## 참가자가 하는 일

1. 부스 Wi-Fi에 연결하고 **운영자가 공유한 부스 링크**를 엽니다. GitHub Pages 주소 뒤에 이 부스를 식별하는 정보가 붙은 링크입니다.
2. Chrome이 로컬 네트워크 연결을 물으면 허용합니다.
3. 모델링 → 실제 슬라이싱 → 출력 대기표 순서로 진행합니다. 설치, CMD, Bambu Studio 실행은 참가자가 하지 않습니다.
4. 출력 상태는 같은 화면에서 확인하고, 출력 시작은 운영자가 현장에서 확인합니다.

한 번 연결한 브라우저는 부스 정보를 기억합니다. 이후 기본 GitHub Pages 주소를 열어도 그 부스에 다시 연결합니다. 처음 사용하는 기기는 공유 링크 또는 화면 위 **부스 연결** 버튼으로 부스를 지정해야 합니다. 주소가 바뀌거나 다른 부스를 사용할 때는 연결을 해제하고 새 링크를 사용합니다.

## 출력 PC 한 대를 한 번 준비

크롬북 대신 프린터 옆 Windows PC 한 대가 슬라이싱과 프린터 통신을 담당합니다. 이 PC와 참가자 기기는 서로 통신 가능한 같은 Wi-Fi에 있어야 합니다.

1. 최신 저장소를 내려받습니다. Node.js 20 이상과 Bambu Studio를 설치합니다.
2. `configure-booth.cmd`를 실행합니다.
3. 프린터 IP·일련번호와 **출력 PC의 Wi-Fi 주소**를 설정합니다. PC 주소와 프린터 주소는 서로 다른 값입니다. 접근 코드는 해당 PC의 Bambu Studio에 저장된 값을 읽거나 비공개 `runtime/config.json`에 입력합니다.
4. 열리는 `http://127.0.0.1:5188/`의 ⚙ 운영자 화면을 PIN으로 엽니다. PIN은 비공개 설정 또는 `runtime/server.log`에 있습니다.
5. **참가자 링크 복사**를 눌러 크롬북에 공유합니다. 기기마다 프로그램을 설치할 필요가 없습니다.

설정한 PC 주소가 바뀌면 `configure-booth.cmd`를 다시 실행하고 새 참가자 링크를 공유하세요. PC의 IP를 DHCP 예약으로 유지하면 링크 관리가 편합니다. 서버가 이미 실행 중이라면 설정 변경 후 기존 서버를 종료하고 다시 시작해야 합니다.

## CMD 창을 계속 띄우지 않으려면

`start-booth.cmd`는 서버를 **백그라운드에서 실행**하고 운영자 화면을 엽니다. 이미 실행 중이면 서버를 중복 실행하지 않습니다. 로그는 `runtime/server.log`, 오류는 `runtime/server-error.log`입니다.

PC 로그인 후에도 자동으로 시작하려면 **출력 PC에서** `install-booth-autostart.cmd`를 한 번 실행합니다. 현재 Windows 사용자의 시작프로그램 바로가기를 만듭니다. PC 전원과 로그인, Wi-Fi, Bambu Studio 설치가 필요하며 행사 중 PC를 절전 상태로 두면 안 됩니다.

자동 시작을 취소하려면 Windows ‘시작프로그램’ 폴더의 **Click Imagination Booth** 바로가기를 제거합니다. 코드 배포 과정에서 사용자의 PC에 자동 시작을 임의로 등록하지는 않았습니다. 학교 정책이 PowerShell 스크립트 실행을 막으면 관리자와 확인하거나 `node bridge/server.cjs`로 직접 실행하세요.

백그라운드 서버를 종료할 때는 작업 관리자에서 이 공방의 Node.js 프로세스를 확인해 종료하거나 Windows에서 로그아웃합니다. 실행 PID는 `runtime/server.pid`에 기록됩니다. 서버 종료가 이미 시작된 프린터 출력을 중지하지는 않습니다.

## 왜 출력 PC가 필요한가

GitHub Pages는 HTML/JS를 배포하는 정적 호스팅이고, 브라우저가 접속만으로 임의의 CMD/프로그램을 실행할 수는 없습니다. 크롬북에는 Windows CMD나 Bambu Studio가 없습니다. 따라서 이 구현은 **크롬북 웹 화면 → 부스 PC → Bambu Studio 슬라이싱 → A1 mini** 구조입니다.

웹에서 임의 프로그램을 실행하는 대신, 출력 PC를 행사 전에 준비하고 켜두면 참가자는 웹만 사용하게 됩니다. 공방은 프린터 IP·일련번호·접근 코드를 참가자 브라우저에 보내지 않습니다. 공유 링크의 부스 키는 작품 접수용이며, 운영자 시작·중지 권한은 포함하지 않습니다.

## Chrome / 학교 네트워크 조건

[Chrome 공식 Local Network Access 안내](https://developer.chrome.com/blog/local-network-access)에 따르면 공개 HTTPS 사이트가 로컬 네트워크에 접속할 때 권한이 필요합니다. 지원하는 Chrome에서는 사설 IP 주소에 대한 HTTP 요청을 권한 승인 후 허용하는 방식입니다. 이 앱은 GitHub Pages와 설정한 부스 PC 사이의 허용된 HTTP API 요청을 사용합니다.

- Chrome의 버전·학교 관리 정책에 따라 로컬 네트워크 권한이 차단될 수 있습니다.
- 같은 Wi-Fi 이름이어도 게스트 격리/AP 격리가 설정되면 참가자 기기와 PC가 통신하지 못할 수 있습니다.
- PC 방화벽에서 이 부스용 서버 통신이 허용되어야 합니다. 앱은 방화벽이나 보안 정책을 자동 변경하지 않습니다.
- Pages 연결에 문제가 있으면 운영자가 공유한 **직접 접속 링크**도 제공합니다. 기기 간 통신 자체가 차단됐다면 직접 링크도 동작하지 않습니다.
- 프린터와 PC의 LAN Only + Developer Mode 및 접근 코드 설정은 기존과 같습니다.
- 현재 제공하는 방식은 같은 네트워크에서 사용하는 부스입니다. 집·학교 등 서로 다른 네트워크 사이의 원격 출력 서버/공개 중계 서비스는 포함하지 않습니다.

## 운영자·접수 보호

기본 실행은 종전처럼 loopback 전용입니다. `--booth` 설정을 한 경우에만 LAN 접수를 엽니다. 지정한 PC 주소·Host, GitHub Pages origin, 접속 키, 요청 토큰을 확인합니다. 참가자는 부스 키와 자신의 무작위 작업 ID로 작품을 접수·확인할 수 있습니다. 운영자 잠금 해제, 전체 대기 목록, 시작·중지·3MF 다운로드는 출력 PC의 loopback 화면에서만 가능합니다.

여러 참가자의 슬라이싱은 한 개씩 순서대로 처리하며 동시에 최대 12개를 접수합니다. 대기표는 모두 같은 출력 PC에서 발급합니다. 실제 프린터는 운영자가 작품 하나씩 시작하며 자동 연속 출력하지 않습니다.

부스 링크는 행사 참가자에게만 공유하세요. 공유 키와 PC 설정은 `runtime/`에 저장하고 공개 GitHub에 넣지 않습니다. 키를 새로 만들면 이전 참가자 링크는 작동하지 않습니다.

## 이번 검증과 남은 현장 확인

- 참가자 두 명의 브라우저와 같은 HTTP 요청을 PC의 LAN 주소로 보내 **실제 Bambu Studio 슬라이싱 → 대기표 1/2 발급 → 운영자 목록 확인 → 시험 대기 취소**까지 검증했습니다. 프린터 명령은 보내지 않았습니다.
- 외부 origin, 부스 키 누락, 다른 Host, 참가자 쪽 운영자 로그인/시작 요청을 거부하는 자동 검사를 통과했습니다.
- GitHub Pages의 새 연결 화면 배포와 HTML 제공을 확인합니다.
- **실제 ChromeOS 기기와 학교 Wi-Fi의 LNA 권한·방화벽·기기 격리 조합은 아직 실기 검증하지 않았습니다.** 현재 작업 환경의 브라우저 자동화가 비활성화되어 이 부분을 확인했다고 주장하지 않습니다.
- 백그라운드·자동 시작 스크립트는 구문을 확인했으며, 사용자의 Windows 시작프로그램을 이번 배포에서 변경하지 않았습니다.

## 화면에서 설정 파일 내려받기

[부스 사이트](https://hichoni.github.io/3d-modeling/)의 **부스 연결 → 운영자 처음 설정 → 운영자 설정 파일 받기 (ZIP)**을 누르세요. `configure-booth.cmd`와 실행에 필요한 공방 파일이 함께 들어 있습니다. ZIP을 폴더에 압축 해제한 뒤 `click-workshop/configure-booth.cmd`를 실행합니다.

- [운영자 설정 묶음 ZIP](https://hichoni.github.io/3d-modeling/downloads/booth-setup.zip)
- [configure-booth.cmd 단독](https://hichoni.github.io/3d-modeling/configure-booth.cmd): 기존 공방 폴더에 넣어 사용하는 파일입니다. 단독 파일만 실행하면 필요한 설정 ZIP을 안내합니다.

설정 묶음은 `node scripts/build.cjs` 실행 시 공개 파일 허용 목록으로 다시 생성합니다. `runtime/`, 학교 프린터 설정, 참가자 출력 파일은 포함하지 않습니다.
